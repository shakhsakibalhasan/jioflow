JioFlow Update182 — Single login approval, no negative-response alerts
Requires Update181.
1. Run Database182.sql in Supabase SQL Editor.
2. Replace ONE runtime file: notifications.mjs.
3. Deploy and refresh once.

A pending login request is displayed once in Pending login approvals. Its matching Recent activity entry is suppressed while pending; duplicate session rows are also collapsed. After the request closes, at most one matching historical feed entry is shown with Request closed. The approval/decline actions, permissions, session controls and 5-second checks are unchanged. Sound keys for the queue and feed use the same login-session key to avoid sounding again when the inbox later includes the same request.

Negative customer-response alerts no longer get created. Existing negative alerts are excluded from the notification feed and its unread count, and defensively hidden by the UI. Historical notification records are retained; customer negative status, notes and follow-up history are not changed.

Local tests: repeated SQL installation, no alert generated by a negative follow-up save, old negative alerts excluded, one pending approval per session across queue/feed, other notices/actions retained, existing password/read/delete/scoping tests and static build passed. Not deployed live.

Order forms: unchanged. The existing customer-details form shows product selection/order summary when editing Confirm status. Processing keeps those controls hidden under the existing confirmed-order workflow.
